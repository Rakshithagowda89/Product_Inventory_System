# Product Inventory System

## Project Overview

The Product Inventory System is a RESTful web application developed using Spring Boot. It manages product details such as product name, category, stock, price, and brand.

The application uses an in-memory `ArrayList` to store product details temporarily. It provides CRUD operations, validation, exception handling, searching, filtering, sorting, and product counting.

No database is required for this project.

## Technologies Used

- Java 17 or later
- Spring Boot
- Spring Web
- Lombok
- Spring Boot Validation
- Maven
- Postman for API testing

## Model Fields

The `Product` model contains six fields:

| Field | Data Type | Description |
|---|---|---|
| productId | Long | Unique identifier generated by the application |
| productName | String | Name of the product |
| category | String | Category of the product |
| stock | Integer | Available quantity |
| price | BigDecimal | Price of the product |
| brand | String | Brand or manufacturer |

## Features

### 1. CRUD Operations

- Add a new product.
- Retrieve all products.
- Retrieve a product by ID.
- Update an existing product.
- Delete a product by ID.

### 2. Validation

The application uses Jakarta Bean Validation annotations.

- `@NotBlank` – Ensures product name, category, and brand are not blank.
- `@Size` – Restricts the allowed length of product name and brand.
- `@Pattern` – Ensures category contains only letters and spaces.
- `@NotNull` – Ensures stock and price are provided.
- `@Min(0)` – Prevents negative stock values.
- `@Positive` – Requires the price to be greater than zero.
- `@DecimalMin` – Ensures the minimum price is 0.01.

### 3. Custom Exception Handling

- `ProductNotFoundException` handles requests for products that do not exist.
- `GlobalExceptionHandler` handles validation failures, invalid request bodies, and invalid arguments.
- HTTP 404 is returned when a requested product ID is not found.
- HTTP 400 is returned for handled validation and bad-request errors.

### 4. Search and Filtering

- Search products using partial product-name matching.
- Filter products by category.
- Filter products within a specified price range.
- Find products with stock below or equal to a specified limit.
- Search products by partial brand name.

### 5. Sorting

- Sort products by price in ascending or descending order.
- Sort products alphabetically by name.
- Sort products by stock in descending order.

### 6. Product Count

Retrieve the total number of products currently stored in the application.

## REST API Endpoints

Base URL:

`http://localhost:8080/products`

| Operation | HTTP Method | Endpoint |
|---|---|---|
| Add product | POST | `/products` |
| Get all products | GET | `/products` |
| Get product by ID | GET | `/products/{id}` |
| Update product | PUT | `/products/{id}` |
| Delete product | DELETE | `/products/{id}` |
| Search by partial name | GET | `/products/search?name=mouse` |
| Filter by category | GET | `/products/category/{category}` |
| Filter by price | GET | `/products/filter/price?min=100&max=1000` |
| Find low-stock products | GET | `/products/low-stock?limit=5` |
| Search by brand | GET | `/products/brand?name=Logitech` |
| Sort by price | GET | `/products/sort/price?direction=asc` |
| Sort by name | GET | `/products/sort/name` |
| Sort by stock | GET | `/products/sort/stock` |
| Count products | GET | `/products/count` |

## Sample API Requests

### Add a Product

**Method:** POST

**URL:** `http://localhost:8080/products`

**Request Body:**

```json
{
  "productName": "Wireless Mouse",
  "category": "Electronics",
  "stock": 25,
  "price": 799.00,
  "brand": "Logitech"
}
```

A successful request returns HTTP `201 Created` with the saved product and its generated ID.

### Get All Products

**Method:** GET

**URL:** `http://localhost:8080/products`

### Get Product by ID

**Method:** GET

**URL:** `http://localhost:8080/products/1`

### Update a Product

**Method:** PUT

**URL:** `http://localhost:8080/products/1`

**Request Body:**

```json
{
  "productName": "Wireless Mouse",
  "category": "Electronics",
  "stock": 30,
  "price": 899.00,
  "brand": "Logitech"
}
```

PUT updates the existing product's fields. All required fields must be supplied.

### Delete a Product

**Method:** DELETE

**URL:** `http://localhost:8080/products/1`

### Search by Partial Name

**Method:** GET

**URL:** `http://localhost:8080/products/search?name=mouse`

Returns products whose names contain the search keyword, ignoring case.

### Filter by Category

**Method:** GET

**URL:** `http://localhost:8080/products/category/Electronics`

### Filter by Price Range

**Method:** GET

**URL:** `http://localhost:8080/products/filter/price?min=100&max=1000`

### Find Low-Stock Products

**Method:** GET

**URL:** `http://localhost:8080/products/low-stock?limit=5`

Returns products with stock less than or equal to five.

### Search by Brand

**Method:** GET

**URL:** `http://localhost:8080/products/brand?name=Logitech`

### Sort by Price

**Ascending:**

`http://localhost:8080/products/sort/price?direction=asc`

**Descending:**

`http://localhost:8080/products/sort/price?direction=desc`

### Sort by Name

`http://localhost:8080/products/sort/name`

### Sort by Stock

`http://localhost:8080/products/sort/stock`

### Count Products

`http://localhost:8080/products/count`

## How to Run the Project

1. Create a Spring Boot project using Spring Tools for Eclipse.
2. Select Spring Web, Lombok, and Validation dependencies.
3. Create the packages and Java classes shown in the project structure.
4. Ensure Lombok is configured correctly in Eclipse.
5. Run `ProductInventoryApplication.java` as a Spring Boot application.
6. Open Postman.
7. Send requests to `http://localhost:8080/products`.

The application runs on port 8080 by default.

## Exception Handling Examples

### Product Not Found

When a product ID does not exist, the API returns HTTP `404 Not Found`.

Example:

```json
{
  "error": "Product Not Found",
  "message": "Product not found with ID: 100"
}
```

### Validation Error

If the product stock is negative, the API returns HTTP `400 Bad Request` with a validation message.

## Important Notes

- Product data is stored in an in-memory `ArrayList`.
- No database is used.
- Product data is lost when the application restarts.
- Product IDs are generated automatically.
- Duplicate product names and stock values are allowed.
- Exact-name matching, SKU validation, duplicate prevention, and inventory-value calculation are not included.
- This project is intended for learning and practicing Spring Boot REST API development.
